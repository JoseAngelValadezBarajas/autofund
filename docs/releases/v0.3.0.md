# AutoFund v0.3.0 — Research Control Center

The first public release. Software version `0.3.0`.

> **No Production-certifiable strategy is bundled or claimed.** This release contains no strategy
> that is certified for real money, and the platform reports zero economically usable alpha sources.
> That is the honest state of the research, not a packaging oversight.

## What this release is

AutoFund makes the question *"does this trading idea deserve capital?"* answerable before capital is
exposed. A hypothesis must survive development, out-of-sample validation, forward capture, economic
validation, risk validation and certification before a human is offered the option to authorize a
session. Most hypotheses do not survive, and `NO_TRADE` is then the correct output.

This release adds **no strategy and no alpha research**. It adds the observability layer that makes
the existing research accountable, and it makes the whole thing safely explorable by someone with no
account.

```text
FRESH CLONE → INSTALL → DEMO MODE → RESEARCH CONTROL CENTER
            → SYNTHETIC EVIDENCE → FULL TEST SUITE
            → ZERO CREDENTIALS → ZERO REAL MONEY → ZERO EXCHANGE MUTATION
```

## Research Control Center

Ten read-only views over a registry rebuilt deterministically from local artifacts, served from
`/api/v1/research`:

- **Overview** — four independent statuses, portfolio, system health, evidence quality, production
  readiness.
- **Alpha Registry** — information sources, with prediction reported separately from economics.
- **Strategy Registry** — engineering, economic, risk and production verdicts as four separate
  columns, so a strategy can be engineering `PASS` and economic `FAIL` on the same row.
- **Experiment Registry** — every milestone with its hypothesis, predeclared windows and outcome.
- **Evidence Explorer** — provenance per record; synthetic and measured are distinguishable.
- **Campaigns** — process health and evidence conclusion reported separately.
- **Activity timeline** — research and production events. Financial events keep their own
  authoritative journal and are not duplicated.
- **Production eligibility** — a deterministic blocking reason for every market and profile pair.
- **Artifact index** — every indexed artifact with a fingerprint.

### The invariant

Four facts are reported and never combined:

| Field | Question |
|---|---|
| Engineering | Is the system running correctly? |
| Research | Is there measured, economically usable evidence? |
| Production | Has a human authorized a live session? |
| Current action | What is AutoFund doing right now? |

A healthy system is not a profitable one, and strong evidence is not permission to trade. The
registry states `statuses_are_independent: true` and the UI renders them as four separate blocks with
distinct visual identities.

## Demo mode

**The default mode.** A fresh clone reaches a working product with no configuration.

- Synthetic dataset, labelled `SYNTHETIC_DEMO`, that has the same scientific shape as the real
  research position.
- No credentials required. Credentials present in the environment are **removed from the process**
  for the duration of the run and restored afterwards.
- No authenticated exchange request and no exchange mutation; both are asserted after startup and a
  violation aborts.
- Writes to `artifacts/demo`, never where a real run reads.
- Works offline. Demo quality does not depend on any exchange being reachable.

```bash
autofund demo
```

Modes: `demo` (default), `shadow` (public data, read-only), `production` (requires credentials and a
per-session operator authorization). An unrecognised mode raises rather than defaulting.

## Execution and recovery

Carried forward from the earlier milestones, and the part of the system that took the most care to
get right:

- Durable journal written **before** any request is sent.
- Single-use submission permit, consumed even if the network call fails, so a retry cannot reuse it.
- Uncertain-order states are first-class: an acknowledged order with no fill evidence is reconciled
  by querying the exchange, never assumed.
- An unresolved order **halts** rather than retrying, because a retry could open a second position.
- Recovery is idempotent: repeating it cannot duplicate a fill, a ledger entry or a position.
- The ledger moves only on confirmed fills.

## Safety boundaries

- Default mode is Demo; Production requires an explicit named choice.
- Authorization is an allowlist: only `RUNNING` authorizes a session, so unknown states are
  unauthorized by default.
- Capital envelope fixed in code: 50 MXN authorized, 25 MXN maximum deployment, 11 MXN maximum
  single order, 0.50 MXN maximum drawdown. No environment variable widens it.
- The only mutating HTTP routes are `POST /api/v1/control/{start,stop,kill}`. There is no
  browser-reachable order endpoint.
- No withdrawal, transfer, cancel or replace capability, and no API permission requested for them.
- No language model influences any financial decision.

## Public-repository hardening

- **Full Git history secret audit** — every blob in every reachable commit, with exact-value matching
  against local credentials. Result: clean.
- **Personal financial data removed** — a real position size and cost basis, and a live round trip's
  exchange identifiers, were published in fixtures and specification documents. All replaced;
  `docs/public-boundary.md` records what was changed and why one derived figure was deliberately
  kept.
- **`.gitignore` hardened** for credentials, runtime state, journals, ledgers, captures and datasets.
- **`.env.example`** rewritten to document all three modes separately, with placeholders only.
- **CI** runs the full test suite, linting, strict typing, frontend checks, the secret scan and a
  demo smoke test, with no credentials and no private data.
- **Documentation** — architecture, research history, security policy, contributing guide, roadmap,
  status and the public/private boundary.

## Known limitations

- **No certified strategy.** Zero.
- **No economically usable alpha source.** The one validated signal measures 2.51 bps against 173 bps
  of friction.
- **Cross-venue dislocation research is unmeasured, not refuted.** The capture covered 0.176 of the
  72 predeclared hours, so it could not have observed a rare event. The negative conclusion was
  correctly overridden by the coverage gate.
- **Maker execution is not implemented as a live mode.** It was researched and modelled: maker/maker
  reduces the fee floor from 157.84 to 121.09 bps and flips no losing pair.
- **Microstructure capture is too short to measure markouts.**
- **MAE and MFE are `NOT_RECORDED`** where no capture exists that could produce them. They are not
  estimated.
- **One exchange adapter**, for a single MXN-quoted venue. Not affiliated with or endorsed by any
  exchange.
- **Windows is the primary development platform.** Linux and macOS are expected to work and the
  commands are documented, but the visual-regression baselines are captured on Windows.
- **No Experiment Engine.** Planned for 0.3.1.

## Upgrading

This is the first public release, so there is no upgrade path to document. The software version
(`0.3.0`) is independent of the research milestone numbering used in `docs/research-history.md`.

### Package metadata correction

`pyproject.toml` declared `version = "0.5.0"` while the product reported `0.3.0` at runtime
(`src/autofund/version.py`). The two had drifted apart, so a built distribution would have been
labelled with a version the running product never reports. Metadata now agrees with the runtime, and
a test asserts that every declaration matches `src/autofund/version.py`, including
`frontend/package.json`.

The build floor was also raised: `pyproject.toml` required `setuptools>=68`, which cannot parse the
PEP 639 license metadata added in this release. The first working release is **77.0.1**, established
by installing candidate versions and building with `--no-isolation` rather than by guessing.

## What this release does not claim

It does not claim profitability. It does not claim any venue partnership. It does not claim that
passing tests makes it safe to point at real capital. It claims that the system can measure, validate
and refuse a trading idea on evidence, and that it reports what it has and has not established with
the same precision.
